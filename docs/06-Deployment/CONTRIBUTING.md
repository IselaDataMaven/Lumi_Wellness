# 1. Welcome

Thank you for contributing to Lumi Wellness.

Every contribution should help create a product that is:

🌿 Compassionate

🤍 Accessible

✨ Reliable

🌸 Human-centered

This guide explains how to contribute effectively.

---

# 2. Contribution Philosophy

Lumi Wellness is built around collaboration and respect.

Contributions should improve:

* User experience
* Product quality
* Accessibility
* Maintainability
* Security

Technical improvements should always consider the human experience.

---

You can contribute through:

## Code

## Design

Examples:

* UI improvements

* Design system updates

## Documentation

Examples:

* Guides

## Testing

Examples:

* Test cases
* Bug reports
* Quality improvements

# 4. Before Contributing

Before starting:

1. Read project documentation

2. Understand the architecture

3. Check existing issues

4. Avoid duplicate work

---

# 5. Development Workflow

Recommended workflow:

```text id="y7v3pp"
Create Branch

↓

Develop Feature

↓

Run Tests

↓

Update Documentation

↓

Create Pull Request

↓

Review

↓

Merge
```

---

# 6. Branch Naming

Branches should follow:

```text id="3k2wq8"
feature/

bugfix/

hotfix/

docs/

refactor/
```

Examples:

```text id="q8m5rv"
feature/ai-journal

bugfix/login-error

docs/update-api-guide
```

---

# 7. Commit Guidelines

Commits should be clear and descriptive.

Format:

```text id="f0m2bx"
type: description
```

Examples:

```text id="9xk3mq"
feat: add wellness journal component

fix: resolve mobile navigation issue

docs: update architecture guide

test: add login test cases
```

---

# 8. Code Standards

All code should follow:

* Clear naming
* Reusable components
* Consistent formatting
* Documentation when needed
* Accessibility practices

Avoid:

* Duplicate logic
* Unnecessary complexity
* Hardcoded values

---

# 9. Frontend Guidelines

React contributions should follow:

* Component-based architecture
* Design System usage
* Responsive principles
* Accessibility requirements

Use:

* Design tokens
* Reusable components
* Shared utilities

---

# 10. Design Contributions

Design changes must consider:

* Existing Design System
* User needs
* Accessibility
* Responsive behavior

New components require:

* Purpose
* Usage examples
* States
* Documentation

---

# 11. AI Contributions

AI-related contributions must include:

* Expected behavior
* Prompt documentation
* Safety considerations
* Evaluation criteria

AI features should prioritize:

* Transparency
* Privacy
* User trust

---

# 12. Testing Requirements

Before submitting changes:

Verify:

□ Application builds

□ Tests pass

□ No existing functionality breaks

□ Accessibility reviewed

□ Documentation updated

---

# 13. Pull Request Guidelines

Every Pull Request should include:

```text id="s4v9cm"
Description

Reason for change

Screenshots if UI changes

Testing performed

Documentation updated
```

---

# 14. Review Process

Reviews should evaluate:

## Technical Quality

* Code quality
* Architecture alignment
* Performance

---

## Product Quality

* User impact
* Accessibility
* Consistency

---

## Security

* Data protection
* Safe implementation

---

# 15. Issue Reporting

Bug reports should include:

```text id="d8k1az"
Title

Description

Steps to reproduce

Expected behavior

Actual behavior

Environment

Evidence
```

---

# 16. Security Issues

Do not publicly disclose security vulnerabilities.

Report them privately following project security guidelines.

---

# 17. Documentation Updates

Documentation should be updated when:

* Architecture changes
* New features are added
* Processes change

Code and documentation should evolve together.

---

# 18. Code of Respect

All contributors should communicate with:

* Respect
* Patience
* Constructive feedback

The goal is collaboration.

---

# 19. Final Principle

Every contribution becomes part of Lumi Wellness.

We build technology, but we serve people.
