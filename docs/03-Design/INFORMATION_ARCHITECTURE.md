# 1. Purpose

This document defines the information architecture of Lumi Wellness.

It describes how content, features, and experiences are organized across the product.

The goal is to create an experience that feels:

🌿 Simple

🤍 Predictable

✨ Easy to navigate

🌸 Supportive

---

# 2. Information Architecture Philosophy

Lumi Wellness organizes information around the user's journey.

The structure should answer:

"What do I need right now?"

Not:

"What features do we have?"

---

# 3. Core Product Areas

Lumi Wellness is organized into five main areas:

```text
Lumi Wellness

├── Home
│
├── Journey
│
├── Activities
│
├── Journal
│
└── Profile
```

# 5. Home

## Purpose

Provide a calm starting point.

The user should immediately understand:

* How they are doing
* What is available
* What they can do next

---

## Content Hierarchy

```text
Home

├── Greeting
│
├── Emotional Check-In
│
├── Recommended Activity
│
├── Current Goals
│
└── Quick Access
```

---

# 6. Journey

## Purpose

Show personal growth over time.

Journey is not a performance dashboard.

It represents:

* Reflection
* Learning
* Progress

---

## Structure

```text
Journey

├── Personal Timeline
│
├── Milestones
│
├── Reflections
│
└── Patterns
```

---

# 8. Journal

## Purpose

Create a private reflection space.

---

## Structure

```text
Journal

├── New Entry

├── Previous Entries

├── Search

└── Personal Insights
```

---

## Journal Principles

The journal should feel:

* Private
* Safe
* Personal

Avoid:

* Public comparison
* Scores
* Rankings

---

Profile

# 10. AI Companion Architecture

Lumi AI is available across the product.

It is not isolated as only a chatbot.

---

## Entry Points

Users can access Lumi through:

* Home suggestions
* Activities
* Journal
* Dedicated AI space

---

## AI Context

Lumi may understand:

* User preferences
* Selected goals
* Previous interactions
* Activity history

Only with appropriate consent.

# 11. Content Hierarchy

Every screen follows:

```text

↓

↓

Supporting Information

```

---

# 12. Search Architecture

Search should prioritize:

1. Personal content

2. Activities

3. Educational resources

4. Settings

---

# 13. User Permissions

Information visibility must respect:

* Privacy
* Consent
* User control

Users should understand:

* What is stored
* Why it is used
* How to manage it

---

# 14. Empty Architecture

Every section needs a first-time experience.

Example:

Journal:

```text
No entries yet.

Your reflections will appear here.

[Write First Entry]
```

# 16. Accessibility Considerations

Information architecture must support:

✔ Clear labels

✔ Predictable navigation

✔ Logical hierarchy

✔ Screen reader navigation

✔ Reduced cognitive load

---

# 17. Architecture Checklist

Before adding a feature:

□ Clear location exists

□ Navigation impact reviewed

□ User goal defined

□ Content hierarchy defined

□ Permissions considered

□ Mobile experience validated
